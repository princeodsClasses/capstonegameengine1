어때요?

AI 가 동작하는 것 잘 봤어요?

그럼 이제 AI( artificial intelligence ) 에 대해 잠깐 살펴볼까요?
AI
  1. 1.명사Artificial Intelligence(인공지능)의 약자.
  2. 2.명사인간의 지적 능력을 모방하여 만들어진, 모종의 것.
  3. 3.IT인간의 지능이 가지는 학습, 추리, 적응, 논증 따위의 기능을 갖춘 컴퓨터 시스템. 전문가 시스템, 자연 언어의 이해, 음성 번역, 로봇 공학, 인공 시각, 문제 해결, 학습과 지식 획득, 인지 과학 따위에 응용한다.

AI는 이렇게 발전해왔어요.

오늘 우리가 쓴 FSM은, 80~90년대에 자리 잡은 방식이에요 — 30년 넘게 지난 지금도, 여전히 제일 많이 쓰이는 방법 중 하나예요.

AI의 종류는 여러 가지가 있어요.

01
FSM (Finite State Machine)
오늘 우리가 다루는 것. 상태 + 전이로 직관적이에요.
02
Behavior Tree
상태 대신 "조건"으로 분기되는 "행동"을 트리 구조로 쌓아요. 재사용 · 조합이 쉬워요.
03
Utility AI
가능한 행동마다 점수(utility)를 매겨서, 매 순간 제일 높은 걸 선택해요. 더 유연하지만, 점수 설계가 까다로워요.
04
GOAP (Goal-Oriented Action Planning)
"목표"만 정해주면, 그걸 이루는 행동 순서를 AI가 스스로 계획해요. F.E.A.R. 같은 게임에서 썼어요.
이 넷은 전부, "무엇을 할지" 행동을 결정하는 쪽이에요. FSM은 상태가 늘어날수록 전이가 기하급수적으로 늘어나서, 수십 개가 되면 Behavior Tree 같은 다른 방식을 더 많이 써요.

그리고, 결이 다른 AI 기법들도 있어요

01
Path Finding (길찾기)
A* 같은 알고리즘으로, 목적지까지 가장 효율적인 경로를 찾아요. 오늘 Chase/Flee의 "직선으로 이동"보다 한 단계 더 똑똑한 이동이에요.
02
Flocking (무리 행동)
주변 개체와 거리 · 방향을 맞추면서, 자연스럽게 무리지어 움직여요. 새 떼 · 물고기 떼 같은 군집 연출에 써요.
03
Machine Learning
규칙을 직접 안 짜고, 데이터를 학습시켜서 행동을 만들어요. 유니티는 ML-Agents라는 패키지로 지원해요.
이 셋은 "무엇을 할지"가 아니라, 어떻게 움직일지 · 어떻게 배울지 쪽이에요. 실제로는 같이 조합해서 써요 — 예를 들어, FSM으로 상태를 정하고 Path Finding으로 실제 이동 경로를 찾는 식으로요.

다시! 상태 패턴 (State Pattern) 이란?

01
정의
상태마다 클래스를 하나씩 만들고, 공통 인터페이스(EnterState · UpdateState · ExitState)로 다뤄요.
02
전이
상태 클래스 안에서, 조건에 따라 캐릭터가 들고 있는 "현재 상태"를 다른 상태 객체로 바꿔치기해요.
03
Why 상태 패턴?
구현이 쉽고, 코드가 유연하고 명확해요. 상태 하나 고치는 게, 그 클래스 하나만 고치면 끝이에요.
04
그런데
전이 조건을 전부 if/else로 직접 짜야 하고, 상태가 몇 개고 어떻게 연결돼 있는지 한눈에 안 보여요.
그래서! 메카님을 사용할거에요!

Mecanim이란 무엇일까요?

01
Animator Controller
상태들을 그래프로 연결해둔, 상태 머신 그 자체예요. Animator 창에서 보는 그 그래프예요.
02
State
네모 상자 하나가, 상태 하나. 애니메이션 클립을 넣어도 되고, 로직만 있는 빈 상태도 괜찮아요.
03
Transition + Parameter
화살표 하나가, 전이 하나. Parameter(대부분 Trigger)로, 언제 넘어갈지 조건을 걸어요.
04
Any State
어떤 상태에 있든 상관없이 갈 수 있는, 공통 전이용 특수 노드예요. Dead로 갈 때 딱이에요.

설계 단계에선 다이어그램으로 그려보면 쉽게 파악할 수 있어요.

대기, 수도 코드로 보면

Idle StateMachineBehaviour
OnEnter
정지한다 대기시간을 랜덤(1~3초)으로 정한다 다음에 갈 패트롤 지점을, 랜덤으로 하나 뽑는다
OnUpdate — 매 프레임
만약 대상이 감지 범위 안이면: 경계로 전이 대기시간이 다 되면: 패트롤로 전이
OnExit
(없음)

패트롤, 수도 코드로 보면

Patrol StateMachineBehaviour
OnEnter
랜덤으로 뽑힌 지점 방향으로, 이동을 시작한다 (moveSpeedNormal)
OnUpdate — 매 프레임
만약 대상이 감지 범위 안이면: 경계로 전이 만약 목표 지점에 도착했으면: 대기로 전이
OnExit
(없음)
웨이포인트가 아니라, 시작 위치 반경 안에서 매번 랜덤으로 지점을 뽑아요 — 그래서 "다음 웨이포인트"가 아니라 "랜덤 지점"이에요.

경계, 수도 코드로 보면

Alert StateMachineBehaviour
OnEnter
정지한다 suspicion(의심치) = 최대치의 절반으로 시작
OnUpdate — 매 프레임
대상 쪽으로 회전한다 만약 대상이 보이면: suspicion 증가 아니면: suspicion 감소 만약 suspicion이 가득 찼으면 (적 확정): 전투 추적으로 전이 만약 suspicion이 0이 되면 (의심 해제): 대기로 전이
OnExit
(없음)

전투 추적, 수도 코드로 보면

CombatChase StateMachineBehaviour
OnEnter
대상 쪽으로, 이동을 시작한다 (moveSpeedCombat)
OnUpdate — 매 프레임
대상 쪽으로 계속 이동하며, 대상 쪽으로 회전한다 만약 사거리 안이면: 발사로 전이
OnExit
(없음)

발사, 수도 코드로 보면

Fire StateMachineBehaviour
OnEnter
대상을 계속 바라보며, 스트레이프(좌우 이동) 방향을 랜덤으로 정한다 쿨다운 = 0 (들어오자마자 한 발)
OnUpdate — 매 프레임
대상을 계속 바라보며, 좌우 스트레이프 이동한다 (moveSpeedCombat) 스트레이프 방향은, 1~2.5초마다 랜덤하게 다시 정한다 쿨다운이 끝나면: 발사한다 (bulletAngle 범위 안에서 방향 랜덤하게 퍼짐) 쿨다운 다시 채운다 만약 거리 > 사거리: 전투 추적으로 전이 만약 체력 ≤ 최대체력 × fleeHpRatio: 전투 도주로 전이
OnExit
스트레이프 이동을 멈춘다 (조준 해제)

전투 도주, 수도 코드로 보면

CombatFlee StateMachineBehaviour
OnEnter
대상 반대 방향으로, 이동을 시작한다 (moveSpeedCombat)
OnUpdate — 매 프레임
대상 반대 방향으로, 계속 이동한다 만약 거리 ≥ 안전거리: 경계로 전이 (일단 돌아가서, 다시 지켜본다)
OnExit
이동을 멈춘다 (도주 속도 원복)

사망, 수도 코드로 보면

Dead StateMachineBehaviour · Any State
OnEnter
정지한다 콜라이더를 끈다 (더 이상 총알에 맞지 않는다)
OnUpdate
(없음)
OnExit
(없음 — 끝 상태. 리셋은 UI에서 따로 처리한다)
6개 상태 중 어디에 있든 상관없이, 체력 ≤ 0이면 Any State 전이로 바로 여기로 와요.

PART 4 · 엔진

수도 코드를 엔진으로 옮겨볼까요?

엔진 열고. 가볼까요?

오늘, 이 것들을 기억해요

✓FSM의 상태(State) · 전이(Transition)는, Mecanim의 Animator Controller로 그대로 옮길 수 있어요.
✓StateMachineBehaviour: OnStateEnter · OnStateUpdate · OnStateExit — 상태 하나하나에 직접 붙는 스크립트예요.
✓같은 Animator Controller를 써도, Animator(오브젝트)마다 변수는 따로 생성돼서 안 섞여요.
✓HP ≤ 0 같은 공통 조건은, Any State 전이로 어떤 상태에 있든 한 곳(Dead)으로 모을 수 있어요.
✓발사처럼 반복되는 행동은, 상태를 안 떠나고 OnStateUpdate 안에서 반복해도 괜찮아요.
✓모든 걸 FSM으로 만들 필요는 없어요 — 총알처럼 상태가 사실상 하나면, 그냥 MonoBehaviour로 충분해요.
출처: 카카오톡 이모티콘 '옴팡이' (작가 애소)
