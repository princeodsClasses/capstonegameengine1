기획? 기획자? 디자이너?
비슷한 듯 다른 이름들
design
  1. 1.명사(건물·책·기계 등의) 디자인(된 형태).
  2. 2.명사디자인(술), 설계(법) (→interior design).
  3. 3.동사(상품·건축물 등을) 디자인 [ 설계 / 도안 ] 하다.
  4. 4.동사(체제·방법 등을) 설계하다.
plan
  1. 1.명사계획 (앞으로 하려는 일)
  2. 2.명사(목표 달성을 위해 고려되는 일련의) 계획 [ 방안 / 방침 ](→master plan)
  3. 3.동사계획을 세우다, 계획하다.
  4. 4.동사계획 [ 의도 / 예상 ] 하다.

한 장 기획서 예제 #01

탈출 모드 (잠입 아님)
환경
맵에 탈출을 위한 통로가 지정되어 있고, 이를 경계하는 적들이 순찰.
미션
적(NPC)를 피해 지정된 탈출구까지 도착.
플레이 시나리오
적은 회전/패트롤하며 감시 → 인지 시 병영 등에서 적이 몰려나옴 → 수량 제한 없음 → 싸우거나 피하며 탈출구까지 이동.
실패 / 성공 조건
실패 : 플레이어 사망  |  성공 : 탈출구까지 도착.
특징 / 보상
주변 적의 인지 범위(시각/청각)를 표현 · 캐릭터 성장을 위한 자원 보상.
퇴치 모드
공통(입장)
로비 > 커뮤니티에서 모드 선택 → 매치 메이킹 대기 → 시작. (대체 Bot / 적 AI 필요)
플레이 방식
플레이어 간 간접 경쟁.
환경
적(NPC) 주둔지 안에서 시작 → 돌아다니며 적을 사살 → 거점에서 지속 출현.
플레이 시나리오
사방에 거점 존재, 적이 배회 → 카운트 다운 후 시작 → 종료까지 시간 카운트 다운 → 처치 수로 순위/보상 결정.
참여 인원
2 ~ 4 명.

한 장 기획서 예제 #02

풍선 터뜨리기 퍼즐 / 콤보
목표
풍선을 연속으로 터뜨려 더 많은 점수 획득.
핵심 플레이
제한 시간 동안 풍선 터치 → 연속으로 터뜨리면 콤보 보너스 획득 → 시간 내 전부 터뜨리면 클리어, 아니면 실패.
진입 / 로비
타이틀 → 로딩 → 로비 진입. 로비에서 여러 메뉴 및 플레이어 정보 확인.
플레이
3D 화면 구성 · 시작 카운트다운 · 랜덤 스폰 · 4방향으로 연결된 동일 색 풍선을 연쇄로 터뜨려 점수 획득.
스테이지
크기 · 등장 색 · 제한 시간을 데이터 테이블에서 로드. 종료 시 연속 진행 여부 확인 후 처리.

바이블, 왜 필요할까요?


기획의 모든 결정과 설정을 한 곳에 모아, 프로젝트 내내 참고하는 통합 문서입니다.
✓팀 전체가 같은 기준으로 작업 — 설정 충돌 / 중복 방지.
✓중간에 합류한 인원도 문서만 보고 빠르게 맥락 파악.
✓프로젝트가 커질수록, 기억이 아니라 문서에 의존.
✓이후 수정 / 확장할 때도 흔들리지 않는 기준점 역할.

유니티 프로젝트, 이렇게 시작할까요?

01
Unity Hub로 새 프로젝트 생성
템플릿(2D / 3D / URP 등) 선택은 우리 팀 프로젝트 성격에 맞춰서.
02
저장 경로 주의
경로에 한글 / 공백 넣지 않기, OneDrive 같은 동기화 폴더 밖에 저장 — 안 그러면 파일 잠금 / 손상이 자주 발생해요.
03
에디터 버전 통일
팀원마다 버전이 다르면 협업 중 충돌 / 오류가 발생하기 쉬워요.
04
필요한 패키지 미리 설치
Package Manager에서 TextMeshPro, Input System 등 팀에서 쓸 패키지를 확인하고 설치해요.

에디터 구성은 이렇게 되어있죠?

이미지를 클릭해서 살펴보세요

Scene

Project

Resource
Resources 폴더 안 에셋은 참조 연결 없이 Resources.Load()로 런타임에 직접 불러올 수 있어요.
Editor
Editor 폴더 안 스크립트는 에디터에서만 동작하고, 빌드에는 포함되지 않아요.
Plug-ins
dll 같은 네이티브 라이브러리나 외부 SDK를 넣는 폴더예요.
Hidden
Unity가 자동으로 감춰서 에셋으로 취급하지 않는 파일 / 폴더예요 — 이름이 . 또는 ~로 시작하거나 .tmp로 끝나면 Project 창에 아예 보이지 않아요.

Console

Collapse
같은 로그가 여러 번 찍혀도 한 줄로 묶어서 보여줘요.
Error Pause
에러 로그가 찍히는 순간 자동으로 Play가 멈춰요 — 원인 상태를 바로 확인할 수 있어요.

Hierarchy

구조화 예시 — 루트 오브젝트 정리
Base
씬의 최상위 루트 오브젝트예요 — 그 아래 UIsRoot / ObjsRoot를 자식으로 둬요.
UIsRoot
Base의 자식. Canvas 등 UI 오브젝트만 모아둬요.
ObjsRoot
Base의 자식. 캐릭터 / 아이템 등 게임 오브젝트를 모아둬요.
검색창 문법
t:type
타입으로 필터링해요. (예: t:Camera → 카메라만 표시)
ref:path/asset
특정 에셋(예: 프리팹)을 참조 중인 오브젝트만 찾아줘요.

Inspector

선택한 오브젝트의 정보
Hierarchy나 Scene에서 클릭한 오브젝트의 컴포넌트 / 속성이 여기 나와요.
컴포넌트 추가 / 제거
Add Component로 기능을 붙이고 뗄 수 있어요.
값 직접 수정
코드를 안 고치고도 여기서 수치를 바로 바꿔서 테스트할 수 있어요.

Game

Game / Simulator
Game(에디터용 미리보기)과 Simulator(실제 기기 화면 비율 / 노치까지 반영한 미리보기)를 전환해요.
Resolution
화면 해상도 / 비율 프리셋을 바꿔가며 다양한 기기에서 어떻게 보일지 테스트해요.
Stats
FPS, 배치(Draw Call), 폴리곤 수 같은 성능 통계를 실시간으로 보여줘요.

Animator / Animation

Mecanim
Unity의 애니메이션 시스템 전체를 가리키는 이름이에요
Animator/Animation 창, 상태 머신, 블렌드 트리를 포함해요.
Finite State Machine
캐릭터의 동작을 여러 '상태'로 나누고, 조건에 따라 상태끼리 전환해요.
(Idle → Move → Jump)
Parameters
상태 전환 조건으로 쓰는 변수예요 (Float / Int / Bool / Trigger).
코드에서 값을 바꿔 상태를 제어해요.
Blend Tree
파라미터 값에 따라 여러 애니메이션을 자연스럽게 섞어서 재생해요.
EX. 이동속도에 따라 걷기 ↔ 달리기
