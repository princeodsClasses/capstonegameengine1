시스템은 건물이 서 있게 하는 골조와 설비를, 콘텐츠는 그 안에서 사람이 살고 느끼는 공간을 만들어요 — (클릭해서 하나씩 지어볼까요?)

전투 공식도, 시스템 디자인이 해요.

숫자 하나도, 그냥 정하는 게 아니라 이렇게 쌓아 올려요
최종 피해량 = 피해량 × (1 + 피해량 증가 비율의 합) + 피해량 증가 값의 합
↳ 피해량 = 최종 공격력 × 방어력 연계 상수 / (방어력 연계 상수 + 최종 방어력)
↳ 최종 공격력 = 공격력 × (1 + 공격력 증가 비율의 합) + 공격력 증가 값의 합
↳ 최종 방어력 = 방어력 × (1 + 방어력 증가 비율의 합) + 방어력 증가 값의 합
→ 각 수치가, 자기만의 공식을 또 가져요
→ 공식도 데이터처럼, 계단식으로 쌓여요.
→ 가능하면, 상수들은 코드에 직접 기재하지 않도록!

시스템 디자인과 데이터, 흔한 오해들.

01
시스템 디자인 ≥ 데이터 테이블
데이터 테이블은, 시스템 디자인이 하는 일 중 하나일 뿐이에요. 안 쓰는 경우도 있고, 다른 파트(서버 등)에서도 써요.
02
"설계, 안 해도 되는 거 아니야?"
조직 성격에 따라 다를 뿐이에요. 시스템 디자이너 · 테크니컬 디자이너 · 혹은 서버 프로그래머가. 역할을 나눠 맡기도 해요.
03
데이터 테이블 ≠ 데이터베이스
이름은 비슷해도, 전혀 다른 거예요. 클릭해서 바로 볼까요?

이런 차이가 있어요.

Datatable
게임에서 사용되는 대량의 다양한 정적 정보를, 구조화하여 포함하는 데이터 형식.
Database
게임에서 생성되는 대량의 다양한 동적 정보를, 구조화하여 저장하는 공간이나, 시스템.
※ 데이터는 게임 제작에 통용되는, 하나의 언어에요!!
정적 데이터 (Datatable)
개발자가 미리 정해두는 것. 게임을 켜도, 안 바뀌어요.
예) 무기 스탯 · 스테이지 정보 · 아이템 테이블
동적 데이터 (Database)
플레이어가 플레이하면서 만들어내는 것. 계속 바뀌어요.
예) 캐릭터 레벨 · 인벤토리 · 점수

PART 4 · 엔진

그럼, 엔진에서는
이 둘을 어떻게 다룰까요?

정적은 정적답게, 동적은 동적답게 — 서로 다른 도구를 써요.
출처: 카카오톡 이모티콘 '옴팡이' (작가 애소)

정적 데이터, 이렇게 다뤄요

01
ScriptableObject
유니티 안에서, 에셋 형태로 직접 만들어두는 데이터예요. Inspector에서 바로 값을 채워 넣어요.
02
CSV (Comma-Separated Values)
표 형태로 정리해서, 대량의 데이터를 엑셀처럼 한 번에 관리해요.
03
..ML (... Markup Language)
조금은 복잡하지만 스키마를 포함하면 안정적으로 사용할 수 있는 언어에요.
XML · YML 등 UNITY 도 YAML 을 사용해요.
04
JSON
구조화된 텍스트 형식이에요. 다른 툴 · 서버와도 쉽게 주고받을 수 있어요.

동적 데이터, 이렇게 다뤄요

01
Memory
플레이어의 기기 안에, 여러 데이터를 휘발성으로 저장해요.
02
PlayerPrefs
이 것도 플레이어의 기기 안에, 간단한 값을 바로바로 저장해요.
03
Redis
서버에서, 빠르게 읽고 쓰는 캐시 · 세션 저장소예요.
04
DB (Database)
서버에서, 오래오래 보관해야 하는 데이터를 저장해요.
같은 "데이터"지만, 정적과 동적은 다루는 도구도 방식도 완전히 달라요.

같은 캐릭터, 다섯 가지로 비교해봐요

7주차 호랑이 · 사자 FSM 그대로예요. Character에 구멍 하나만 뚫어뒀어요.
Character ① 직접 스크립트에 변수 할당
protected virtual void LoadExternalStats() { } // 비워두면 — Inspector에 직접 써넣은 값 그대로 써요 (지금까지 하던 방식)
그리고, 나머지 네 가지는 전부 이 클래스 하나만 오버라이드해서
CharacterFromScriptableObject : Character // ② 스크립터블 오브젝트 로드 CharacterFromCSV : Character // ③ CSV 로드 CharacterFromXML : Character // ④ XML 로드 CharacterFromJSON : Character // ⑤ JSON 로드 // 각자, LoadExternalStats()만 오버라이드해서 // 자기 소스에서 값을 읽어와 SetStats(...)를 불러요
호랑이 · 사자 모델도, FSM 상태도, 전투 로직도 전부 그대로예요 — 바뀌는 건 "스탯이 어디서 오는가" 한 곳뿐이에요.

다섯 가지, 이런 차이가 있어요

다섯 다, 결과(호랑이·사자가 싸우는 것)는 완전히 똑같아요 — 데이터를 "어디에 두고, 누가 쉽게 고칠 수 있는가"만 달라요.

ScriptableObject 버전

유니티 에셋 그 자체예요. 코드 없이, 기획자가 Inspector에서 값만 바꿔도 돼요. PlayFSM_SO
실제 에셋 Inspector
읽는 코드 CharacterFromScriptableObject.cs
public class CharacterStatsSO : ScriptableObject { public float hp, bulletDamage, bulletAngle; public float moveSpeedNormal, moveSpeedCombat; } [SerializeField] private CharacterStatsSO _statsAsset; protected override void LoadExternalStats() { SetStats( _statsAsset.hp, _statsAsset.bulletDamage, _statsAsset.bulletAngle, _statsAsset.moveSpeedNormal, _statsAsset.moveSpeedCombat ); }
Tiger_SO / Lion_SO 프리팹의 Inspector에, 이 에셋을 그냥 드래그해서 끼워뒀어요.

CSV 버전

엑셀처럼 표로 관리 — 대량의 데이터를 줄 단위로 읽어요. PlayFSM_CSV
실제 파일 CharacterStats.csv
namehpbulletDamagebulletAnglemoveSpeedNormalmoveSpeedCombat
Tiger801553.52
Lion12010152.51.2
읽는 코드 CharacterFromCSV.cs
[SerializeField] private string _characterKey = "Tiger"; [SerializeField] private TextAsset _csvFile; protected override void LoadExternalStats() { string[] lines = _csvFile.text.Split('\n'); for (int i = 1; i < lines.Length; i++) // 헤더는 건너뜀 { string[] cols = lines[i].Trim().Split(','); if (cols[0] != _characterKey) continue; SetStats(float.Parse(cols[1]), float.Parse(cols[2]), float.Parse(cols[3]), float.Parse(cols[4]), float.Parse(cols[5])); return; } }
콤마(,)로 쪼개고, 0번째 칸(이름)이 _characterKey랑 같은 줄을 찾아요.

XML 버전

태그로 구조를 감싸요 — 스키마로 형식을 강제하기 좋아요. PlayFSM_XML
실제 파일
Resources/Data/CharacterStats.xml <CharacterStatsList> <CharacterStats name="Tiger"> <hp>80</hp> <bulletDamage>15</bulletDamage> <bulletAngle>5</bulletAngle> <moveSpeedNormal>3.5</moveSpeedNormal> <moveSpeedCombat>2</moveSpeedCombat> </CharacterStats> <CharacterStats name="Lion"> <hp>120</hp> <bulletDamage>10</bulletDamage> <bulletAngle>15</bulletAngle> <moveSpeedNormal>2.5</moveSpeedNormal> <moveSpeedCombat>1.2</moveSpeedCombat> </CharacterStats> </CharacterStatsList>
읽는 코드 CharacterFromXML.cs
[SerializeField] private string _characterKey = "Tiger"; [SerializeField] private TextAsset _xmlFile; protected override void LoadExternalStats() { XDocument doc = XDocument.Parse(_xmlFile.text); var node = doc.Root.Elements("CharacterStats") .FirstOrDefault(e => (string)e.Attribute("name") == _characterKey); SetStats( (float)node.Element("hp"), (float)node.Element("bulletDamage"), (float)node.Element("bulletAngle"), (float)node.Element("moveSpeedNormal"), (float)node.Element("moveSpeedCombat") ); }
System.Xml.Linq의 XDocument로, name 속성이 일치하는 노드 하나를 찾아요.

JSON 버전

가장 가볍고 범용적 — 서버 · 웹과도 그대로 주고받아요. PlayFSM_JSON
실제 파일
Resources/Data/CharacterStats.json { "list": [ { "name": "Tiger", "hp": 80, "bulletDamage": 15, "bulletAngle": 5, "moveSpeedNormal": 3.5, "moveSpeedCombat": 2 }, { "name": "Lion", "hp": 120, "bulletDamage": 10, "bulletAngle": 15, "moveSpeedNormal": 2.5, "moveSpeedCombat": 1.2 } ] }
읽는 코드 CharacterFromJSON.cs
[SerializeField] private string _characterKey = "Tiger"; [SerializeField] private TextAsset _jsonFile; protected override void LoadExternalStats() { var data = JsonUtility .FromJson<CharacterStatsJsonList>(_jsonFile.text); foreach (var entry in data.list) { if (entry.name != _characterKey) continue; SetStats(entry.hp, entry.bulletDamage, entry.bulletAngle, entry.moveSpeedNormal, entry.moveSpeedCombat); return; } }
원래 PlayFSM부터 PlayFSM_SO · _CSV · _XML · _JSON까지, 씬 5개 다 열어서 똑같이 돌아가는지 비교해볼까요?

오늘, 이 것들을 기억해요.

✓데이터 설계 등의 작업은 시스템 디자인이 하는 일 중 하나일 뿐이에요.
✓데이터는 게임 제작에서 통용되는 하나의 언어예요.
✓정적 데이터 ( 테이블 등 ) 와 동적 데이터 ( 데이터 베이스 등) 으로 구분해요.
✓정적 데이터는 ScriptableObject · CSV · JSON 등의 방법으로, 동적 데이터는 PlayerPrefs · Redis · DB 등으로 다뤄요.
