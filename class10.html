이제 엔진으로?

엔진에서 소리를 사용해볼까요?

Unity 오디오의 기본 구성

AudioClip
재생할 음원 데이터. BGM · 명중음 · 대사 등을 준비해요.
→
AudioSource
클립을 실제로 재생해요. 반복 · 음량 · 공간 설정을 담당해요.
→
AudioListener
어디서 듣는지 정해요. 보통 카메라에 Listener 하나를 둬요.
AudioManager가 하는 일
여러 Source와 클립을 관리해 사건이 발생한 곳에서 키로 재생을 요청하게 해요.

AudioClip, 재생할 소리 데이터

설정고를 기준오늘 기준
Load Type짧고 자주 재생 = Decompress On Load,
길고 용량 큰 음원 = Streaming		SFX는 Decompress,
BGM은 Streaming
Compression Format용량을 줄이려면 Vorbis, 음질이 더 중요하면 PCM기본은 Vorbis
Force To Mono방향성이 중요하지 않은 효과음이면 켜요SFX는 켜는 걸 고려해요
Preload Audio Data재생 지연 없이 바로 써야 하면 켜요자주 쓰는 SFX는 켜둬요
오늘 기준
BGM은 Streaming, SFX는 Decompress On Load로 기본 설정해요. 느껴지는 지연과 로딩 시간이 서로 다른 이유예요.

AudioSource, 소리를 재생하는 컴포넌트

Play On Awake은 꺼둬요
켜져 있으면 씬이 시작되자마자 재생돼요. 코드로 원하는 순간에 재생하려면 OFF로 바꿔요.
Loop은 BGM에만
계속 이어질 곡만 Loop을 켜요. 한 번 울리면 끝나는 SFX는 꺼둬요.
Spatial Blend로 2D/3D
0이면 2D(거리 무관), 1이면 3D(Listener와의 거리로 음량이 변해요).
AudioManager의 채널
BgmSource · SfxSource처럼, 역할별로 AudioSource를 따로 둬요. 하나의 GameObject에 여러 개를 붙일 수도 있어요.

AudioListener, 소리를 듣는 기준

보통 카메라에 있어요
Main Camera에 기본으로 붙어있어요. 플레이어가 서 있는 자리를 귀로 삼아요.
씬에 하나만 켜둬요
Listener가 2개 이상 활성화되면 경고가 떠요. 카메라를 전환할 땐 하나만 남겨요.
위치가 3D 음량을 결정해요
Spatial Blend가 3D인 소리는 Listener와의 거리로 음량이 달라져요.
흔한 실수
씬에 카메라가 여러 개면 Listener도 여러 개가 될 수 있어요. 필요 없는 쪽은 AudioListener 컴포넌트를 꺼두세요.

AudioManager, 이렇게 설계해요

어디서나 하나
SingletonMono 패턴이에요. 씬이 바뀌어도 하나만 남아서, 어디서든 AudioManager.Singleton으로 접근해요.
BGM은 2채널
한 곡이 끝나길 기다리지 않아요. 다른 채널에 새 곡을 올려 겹쳐 재생하면서 크로스페이드해요.
SFX는 채널 풀
미리 만들어둔 20개 채널 중 비어있는 걸 꺼내 써요. 여러 효과음이 겹쳐도 서로 끊기지 않아요.
이건 각자 바꿔봐요.
지금은 Resources.Load로 클립 이름만 넘기면 재생돼요. 각 프로젝트에서 사용하는 데이터를 받아서 처리하도록 바꿔봐요.

BGM은 키로 요청해요.

장면의 상태가 바뀌는 시점
AudioManager.Singleton.PlayBGM("bgm_Lobby");

// 전투 진입이 확정됐을 때
AudioManager.Singleton.PlayBGM("bgm_PlayFSM2");

// 전환 시간을 0으로 주면 즉시 전환돼요.
AudioManager.Singleton.PlayBGM("bgm_Lobby", 0f);

// 침묵도 연출이에요.
AudioManager.Singleton.StopBGM();
같은 곡은 처음부터 다시 틀지 않아요
같은 키가 재생 중이면 요청을 무시해요. Update에서 매 프레임 호출하지 말고 상태 변화에 연결해요.
기본 전환은 1초
새 곡과 이전 곡을 두 채널에서 겹쳐요. 전환 시간은 호출할 때 직접 바꿀 수 있어요.

두 채널로 교차 전환해요.

두 채널이 반대로 움직여요
이전 곡은 음량을 내리고 새 곡은 동시에 올려요. 전환이 끝나면 이전 채널은 완전히 멈추고, 새 채널만 남아요.

SFX는 사건이 확정된 순간에

명중 처리에서 호출
// 화면 전체에서 들리는 2D 효과음
AudioManager.Singleton.PlaySFX("footstep");

// 0.3초 늦게 재생하고 싶을 때
AudioManager.Singleton.PlaySFX("footstep", 0.3f);

// 맞은 지점에서 들리는 3D 효과음
AudioManager.Singleton.PlaySFX3D("footstep", hitPoint);

// 지연 예약까지 취소
AudioManager.Singleton.StopSFX();
공격 입력과 명중 결과를 구분해요
단발 SFX는 PlayOneShot과 비슷하게 겹쳐 울려요. 3D 모드는 호출할 때 넘긴 위치로 공간감을 줘요.
지연은 채널을 고르기 전이에요
delay만큼 기다린 뒤에 빈 채널을 찾아요. 채널이 다 차 있으면 그 요청만 조용히 생략돼요.

음량과 무음을 따로 조절해요.

Slider / Toggle과 연결할 공개 함수
AudioManager.Singleton.SetBgmVolume(0.5f);
AudioManager.Singleton.SetSfxVolume(0.8f);

// 일시적인 전체 무음
AudioManager.Singleton.SetMuted(true);
AudioManager.Singleton.SetMuted(false);
BGM / SFX 음량은 따로 움직여요
SetBgmVolume · SetSfxVolume은 서로 영향을 안 줘요. SetMuted는 BGM 채널만 즉시 0으로 낮춰요.
Audio Mixer는 선택 연결
BGM / SFX Output 그룹을 연결하면 라우팅돼요. 연결 안 해도 재생 자체는 동작해요 — 믹서가 없으면 씬 전환 시 스냅샷 전환만 조용히 건너뛰어요.

코드 어디에서 부를까요?

씬이 시작될 때
씬 진입 지점에서 그 씬의 BGM과 믹서 스냅샷을 함께 요청해요 — ChangeAudioMixSnapshot(scene) 한 번으로요.
애니메이션이 지나갈 때
발소리처럼 반복되는 효과음은 AnimationEvent가 호출하는 메서드 안에서 PlaySFX를 불러요.
판정이 끝났을 때
공격 명중처럼 결과가 확정된 순간에 PlaySFX / PlaySFX3D를 불러요. 입력 시점이 아니라 결과 시점이에요.
공통 원칙
상태가 바뀌는 지점에 붙여요. Update에서 매 프레임 부르면 같은 소리가 계속 재요청돼요.

재생 기능이 정리하는 것들

전환과 반복
같은 BGM을 다시 요청해도 재시작하지 않아요. 전환 도중 다른 곡으로 또 바꿔도 끊기지 않고 이어져요.
무음과 지연의 관계
무음 중에 예약된 지연 SFX는 취소되지 않아요 — 대기 시간이 끝나면 음량 0으로 조용히 재생돼요.
이름과 거리
클립 이름이 틀리면 콘솔에 경고가 떠요. 3D 소리는 Listener와의 거리로 음량이 자동으로 달라져요.
소리가 안 나면
Clip 경로(Resources/Audios/...) → 사용자 음량/무음 → Source/Listener → 3D 거리 → 출력 장치를 차례로 확인해요.
