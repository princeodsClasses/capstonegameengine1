PART 3 · 엔진

자, 이제 엔진 고고?

프로젝트를 실제로 만들고, 씬과 게임 오브젝트 구조를 제대로 잡아봅시다.
출처: 카카오톡 이모티콘 '옴팡이' (작가 애소)

이제 진짜 프로젝트를 만들어볼까요?


git clone도, Unity Hub의 새 프로젝트 생성도 — 둘 다 빈 폴더를 요구해요. 순서를 잘못 잡으면 서로 부딪혀요.
01
Unity 프로젝트부터 만들기
최종 경로에 Unity Hub로 새 프로젝트를 바로 생성하세요. 템플릿(2D / 3D / URP 등)은 팀 프로젝트 성격에 맞춰서.
02
.gitignore부터 준비
첫 커밋 전에, Library · Temp · obj · Build 등을 제외하는 .gitignore를 넣어두세요.
03
그 자리에서 저장소 만들기
Sourcetree의 생성(Create) 탭에서 이미 파일이 있는 그 폴더를 그대로 선택하세요 — 추가(Add) 탭은 이미 git 저장소인 폴더에만 쓰는 거라, 지금처럼 빈 프로젝트 폴더에 쓰면 에러가 나요.
04
원격 저장소는 비워서 생성
GitHub에서 README 없이 빈 저장소로 만들면, 이후 git push가 충돌 없이 깔끔해요.
이미 clone부터 했다면? 다른 빈 폴더에 Unity 프로젝트를 만든 뒤, 생성된 파일을 클론 폴더로 옮겨도 결과는 같아요.

여러 명이 함께 작업하려면?

01
Collaborator 등록
Public 저장소라도, 팀원이 push하려면 Settings > Collaborators에서 초대해야 해요.
02
Personal Access Token(PAT) 사용
GitHub는 더 이상 계정 비밀번호로 push를 허용하지 않아요. 로그인 창에 비밀번호 대신 PAT을 입력하세요.
03
토큰은 이렇게 발급
Settings > Developer settings > Personal access tokens에서, 만료 기간 · 권한 범위를 정해 발급해요.
04
SSH 키도 대안이에요
토큰을 매번 입력하기 번거로우면, SSH 키를 등록해두는 방법도 있어요.

먼저, GitHub에 가입해요

github.com에서 이메일 · 비밀번호 · 아이디만 있으면 가입 끝 — 학교 이메일이면 학생 인증으로 Pro 혜택도 받을 수 있어요.

개인 토큰 (Personal Access Token) 발행

Settings > Developer settings > Personal access tokens에서 발급 — 이름(Note), 만료 기간, repo 권한 범위를 체크하면 끝이에요.

Git Client, Sourcetree

명령어 없이 Git을 편하게 쓰게 도와주는 앱이에요 — sourcetreeapp.com에서 설치하고, GitHub 계정을 연결해두세요.

보관소 (Repository) 생성 — 웹에서

GitHub에서 New repository로 팀 저장소를 만들고, 초록색 Code 버튼에서 clone용 주소(HTTPS)를 복사해두세요.

보관소 (Repository) 생성 — Sourcetree에서

Sourcetree의 생성(Create) 탭에서 로컬 경로와 연결할 계정 · 소유자를 지정하면, 로컬 + 원격 저장소를 한 번에 만들 수 있어요. (추가 탭과는 달라요 — 추가는 이미 있는 저장소를 등록할 때만 써요.)

Git Clone

Sourcetree의 Clone 탭에서 저장소 주소와 저장할 로컬 폴더를 지정하면, 그 폴더로 내려받아(clone) 작업을 시작할 수 있어요.

Staging이란?

01
정의
다음 커밋에 포함할 변경사항을, 미리 골라두는 임시 영역이에요.
02
왜 필요할까
수정한 파일 중 일부만 골라서 커밋하고 싶을 때 유용해요.
03
Sourcetree에서는
파일 목록의 체크박스를 클릭하면, 그 파일이 Staged 영역으로 이동해요.
04
아직 저장된 건 아니에요
Staging은 커밋 전 준비 단계일 뿐, 실제 기록은 Commit에서 일어나요.

Commit이란?

01
정의
Staging된 변경사항을, 메시지와 함께 로컬 저장소에 기록(스냅샷)하는 것.
02
커밋 메시지
"무엇을, 왜 바꿨는지" 짧고 명확하게 적어요 — 나중에 히스토리를 훑을 때 큰 도움이 돼요.
03
로컬에만 저장돼요
Commit은 내 컴퓨터에만 기록돼요. 팀원에게 공유하려면 Push가 필요해요.
04
자주, 작게
한 번에 너무 많은 변경을 몰아서 커밋하지 말고, 의미 단위로 나눠서 자주 커밋해요.

Push란?

01
정의
로컬 저장소에 쌓인 커밋들을, 원격 저장소(GitHub)로 업로드하는 것.
02
이제 팀원도 볼 수 있어요
Push해야 비로소, 다른 팀원이 내 변경사항을 받아볼 수 있어요.
03
Pull과 세트예요
Push하기 전에 먼저 Pull로 최신 상태를 받아오면, 충돌을 줄일 수 있어요.
04
충돌(Conflict)이 나면
같은 파일을 동시에 고치면 충돌이 날 수 있어요 — 당황하지 말고 하나씩 해결해요.

정리하면, 이렇게 순환해요

↻
매번 반복돼요
📥
STEP 1
Pull
저장소의 최신 상태를 받아와요.
✏️
STEP 2
Working
파일을 직접 수정 ( 작업 ) 하는 단계에요.
📋
STEP 3
Staging
( 작업 후 수정 되어 ) 커밋할
파일을 분류하고요.
💾
STEP 4
Commit
메시지와 함께 로컬에 기록해요.
☁️
STEP 5
Push
원격 저장소에 반영해요.

협업, 규칙부터 정해요

✓브랜치 전략을 먼저 정하세요
예: main + 기능별 브랜치 or 버전 브랜치.
✓Text 가 아닌 파일은 동시에 건드리면 충돌이 잦아요 — 작업 전 미리 얘기해요.
.unity / .prefab 등..
✓.meta 파일도 반드시 함께 커밋하세요. 안 그러면 참조가 깨져요. meta 파일은 에셋들의 속성 등 정보를 가지고 있는 필수 파일이에요.
✓커밋 메시지 규칙을 정해두면, 나중에 히스토리 찾기가 훨씬 편해요.
자주 사용하는 컨벤션 예도 있지만, 우리만의 것을 만드는 것도 좋아요.
✓커밋 단위는 Task 단위로.!
Revert 하거나 브랜치에서 Merge 할 때 등 편리해요.

뭘 빼고, 뭘 올려야 할까요?

.gitignore 이건 빼세요
Library/
에디터가 매번 새로 생성하는 캐시 폴더.
Temp/ · Obj/ · Build/
임시 빌드 산출물, 커밋할 필요 없어요.
.vs/ · UserSettings/
개인 에디터 설정, 팀원마다 달라도 되는 값.
*.csproj · *.sln
IDE가 자동으로 다시 만들어주는 파일.
TIP
GitHub 웹에서 저장소 만들 때, Unity용 .gitignore 템플릿을 바로 추가할 수 있어요.
Repository 이건 올리세요
Assets/
스크립트 · 씬 · 프리팹 등 실제 콘텐츠 전부 — 폴더 곳곳의 .meta 파일도 각 에셋에 자동으로 딸려가니, 실수로 gitignore하지 않게 주의하세요.
Packages/
프로젝트가 어떤 패키지를 쓰는지 정의하는 목록.
ProjectSettings/
태그 · 레이어 · 빌드 설정 등, 프로젝트 전역 설정.

Scene이란 무엇일까요?

01
정의
게임의 한 장면(레벨 · 메뉴 · 화면)을 표현하는, GameObject들의 컨테이너예요.
02
파일 단위
씬 하나 = .unity 파일 하나. 씬을 나누는 건, 결국 파일을 나누는 것과 같아요.
03
독립된 Hierarchy
씬마다 서로 다른 오브젝트 구성을 가지고, 로드된 씬의 오브젝트만 메모리에 올라와요.
04
한 프로젝트엔 여러 씬
새 프로젝트를 만들면 기본 씬이 하나 생기고, 필요에 따라 씬을 추가해나가요.

씬, 왜 나눌까요?

01
서로 다른 상태를 표현해요
타이틀, 로비, 인게임처럼, 게임이 거치는 서로 다른 화면/상태를 씬 단위로 나눠요.
02
메모리를 아낄 수 있어요
지금 로드하지 않은 씬의 오브젝트 · 에셋은 메모리에 올라오지 않아요.
03
협업도 쉬워져요
각자 다른 씬 파일을 맡으면, 같은 파일을 동시에 건드릴 일이 줄어요.
04
무한정 나누지는 않기
너무 잘게 나누면, 씬 전환 관리가 오히려 복잡해질 수 있어요.

씬, 등록하고 이름 붙이기

01
Build Profiles에 등록
File > Build Profiles > Scene List 에서,
사용할 씬을 순서대로 추가해요.
02
Index 도 중요해요.
String 으로도 사용하지만, 등록된 Index 로 사용하기도 해요.
03
안 쓰는 씬은 정리
테스트용 씬이 쌓이면, 나중에 어떤 게 진짜인지 헷갈려요.
최근 유니티(6.2+)는 이름이 Build Profiles로 바뀌었어요.
Scene List에 등록된 씬마다 순서(인덱스) 번호가 매겨져요.

씬, 어떻게 전환할까요?

01
SceneManager.LoadScene()
코드로 다음 씬을 불러오는, 가장 기본적인 방법이에요.
02
Single vs Additive
Single은 기존 씬을 지우고 교체, Additive는 기존 씬 위에 겹쳐서 로드해요.
03
씬 간 데이터 전달
정적 클래스, 싱글톤, 혹은 DontDestroyOnLoad 오브젝트를 활용해요.
04
로딩 화면
씬이 무거워지면, 비동기 로드(LoadSceneAsync)로 로딩 바를 보여줘요.

코드로는, 이렇게 생겼어요

기본 전환 코드 예시
using UnityEngine.SceneManagement; public class SceneLoader : MonoBehaviour { public void GoToScene(string sceneName) { SceneManager.LoadScene(sceneName); } }
비동기 로딩 코드 예시
IEnumerator LoadAsync(string sceneName) { var op = SceneManager.LoadSceneAsync(sceneName); while (!op.isDone) yield return null; }

오브젝트란 무엇일까요?

01
정의
유니티에 존재하는 모든 구성 요소의 기본 단위예요. 제일 기본형은 Create Empty!
02
형태
눈에 보이는 시각적 요소(캐릭터, 배경)일 수도, 눈에 안 보이는 비시각적 요소(매니저, 트리거)일 수도 있어요.
03
Component를 담는 그릇.
다양한 Component들을 붙일 수 있어요.
04
기본 Component 는 Transform.
존재 자체를 정의하는 Transform Component 가 기본으로 포함되어 있어요.
Screen Space 로 배정되는 Canvas 아래 UI 오브젝트들에는 RectTransform이 자동으로 배정되요.

오브젝트의 종류

01
GameObject
2D / 3D · Effect · Light · UI · Audio · Video 등, 하이어라키에 직접 만드는 실체.
02
Prefab
GameObject를 저장해서, 여러 씬에서 반복 사용할 수 있게 만든 에셋.
03
Scene
여러 GameObject를 담고 있는, 하나의 큰 오브젝트 모음집이에요.
Hierarchy의 + 버튼(또는 GameObject 메뉴)을 누르면 실제로 이 목록이 떠요.

게임 오브젝트, 어떻게 이루어져 있을까요?

01
GameObject = 빈 그릇
그 자체로는 아무 기능도 없는, 이름과 위치만 가진 컨테이너예요.
02
Transform은 항상 붙어있음
위치 · 회전 · 크기, 모든 오브젝트가 기본으로 가지고 있어요.
03
Component 조합으로 기능 완성
Collider, Rigidbody, 직접 만든 스크립트 등을 붙여서 동작을 만들어요.
04
Prefab으로 재사용
자주 쓰는 오브젝트는 프리팹으로 만들어, 여러 곳에서 재사용해요.

컴포넌트란 무엇일까요?


오브젝트에 부착되어, 동작하거나 특성을 정의하는 모듈이에요.
01
Layout
Transform, RectTransform처럼 위치 / 배치를 담당해요.
02
Physics
Rigidbody, Collider처럼 충돌 / 중력 같은 물리를 담당해요.
03
Animation / Audio
Animator, AudioSource처럼 움직임과 소리를 담당해요.
04
Script
우리가 직접 만드는 동작 — 결국 이것도 하나의 컴포넌트예요.

컴포넌트의 특징

✓
재사용성
한 번 만든 컴포넌트를, 다른 오브젝트에도 그대로 붙일 수 있어요.
✓
동시성
여러 컴포넌트를 한 오브젝트에 동시에 붙여서, 조합으로 동작을 만들어요.
✓
확장성
상속을 활용해서, 기존 컴포넌트를 바탕으로 더 발전시킬 수 있어요.
✓
편의성 / 조작성
Inspector에서 값을 바로 조정하며 테스트할 수 있어요.
아. 징그러..!

계층 구조, 처음부터 정리해요

✓루트를 무작정 늘어놓지 마세요.
Base 하나 아래로 정리하면 한눈에 보여요.
✓UI와 게임 오브젝트는 폴더처럼 나눠 담으세요

✓빈 오브젝트(Empty GameObject)로 그룹핑하면,

✓이름 규칙을 미리 정하세요.
Player, Enemy_Boss처럼 팀 전체가 통일해서.
